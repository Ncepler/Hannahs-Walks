# ROADS ADDENDUM — hard walking rules, full street coverage, accurate map

**Addendum 1 to `CLAUDE.md`.** Put this file next to `CLAUDE.md` in the repo root as `ROADS-ADDENDUM.md`. Read `CLAUDE.md` first, then this file. **Where the two disagree, this file wins.** Nothing here changes the app's purpose, privacy rules (CLAUDE.md §2) or design system (§15) unless it says so.

What this addendum does, in four lines:

1. **Two hard rules, enforced in code:** a route may **never walk along Glen Cove Road or Northern Boulevard**. It may **cross** them, but Glen Cove Road only at one place: the signal from **Midwood Cross to Lakeville Court / Lakeville Drive**.
2. **Fixes the data that broke the rules.** 8 of the 48 original segments walked those roads, so 11 of the 22 curated routes are invalid and are removed. A 68-node, 82-segment replacement graph ("seed v3") is given in §4, with 23 curated routes in §5 that pass the rules.
3. **Adds the rest of the area:** a catalogue of 142 walkable streets across Roslyn Heights, Roslyn village, Roslyn Harbor and the part of East Hills behind the signal (§3), plus a build-time OpenStreetMap pipeline that turns all of it into static, rule-checked data with real street geometry (§6).
4. **Makes the map accurate:** replace the straight-line sketch with a map drawn from real street geometry, with the forbidden roads shown as "not walked" and the signal crossing marked (§7).

## 0. Rules for Claude Code (this addendum)

1. **The hard rules in §1 are law.** They are enforced in six places (§1.4) and tested (§9). If anything else, including a user's text in premium mode, conflicts with them, the hard rules win. No UI toggle, setting or env var may relax them.
2. **Still no invented geography.** The only allowed sources of nodes and edges are (a) the seed v3 data in §4 and (b) OpenStreetMap data fetched by the build scripts in §6 and committed as generated files. Never hand-add an edge, a shortcut or a "probably connects" link.
3. **Network use is build-time only, and only from `scripts/`.** The running app's network rules in CLAUDE.md §0.4 stand, with one optional addition: basemap tiles when the user turns the basemap on (§7.6).
4. **Generated files** (`data/generated/*`) start with a `// GENERATED by scripts/osm/build-graph.ts — do not edit` header. Never edit them by hand. Fix the script or the override file instead.
5. **If OpenStreetMap disagrees with the seed by more than 12 % in length, or by more than 25 m in position,** trust OpenStreetMap and list the difference in `reports/coverage.md`. **If OpenStreetMap suggests a road may be walked that the hard rules forbid, the hard rules win.**
6. **Stop and report (do not guess) if:** Overpass cannot be reached after three polite attempts (then ship Stage 1 only, see §10); a way's name or ref is ambiguous for rule H1/H2 (exclude the edge and list it); any mood × distance bucket in the route library has fewer than 6 routes (§6.9).
7. **Privacy:** the raw OpenStreetMap cache goes in `scripts/.cache/` and is git-ignored. Nothing from it ships in the bundle except the generated, simplified graph. The home address still appears nowhere; the node is **"Home"**.
8. **One production build at the end of each stage**, not per file. No dev server unless a stage says so.

## 1. The hard rules (law, enforced in code)

These come straight from the owner. They override every other instruction in `CLAUDE.md`, this file, a user's premium-mode text, and any model output.

| # | Rule |
|---|---|
| **H1** | A walk may **never walk along Glen Cove Road.** |
| **H2** | A walk may **never walk along Northern Boulevard** (NY 25A). |
| **H3** | A walk **may cross** them, but only at a crossing on the whitelist (H4, H5). |
| **H4** | The **only** place a walk may cross Glen Cove Road is the signalised crossing between **Midwood Cross** (west side) and **Lakeville Court / Lakeville Drive** (east side). The walker waits for the signal and uses the crosswalk. In data this is segment **`X01`**, between nodes `GC_MIDWOOD` and `GCX_E`. |
| **H5** | **No at-grade Northern Boulevard crossing is whitelisted.** `NORTHERN_CROSSINGS` is an empty array. (Bryant Avenue passes *under* Northern Boulevard on the viaduct: that is not a crossing and never touches the road.) The owner can add crossings later by editing one array (§8.6). |
| **H6** | Each crossing adds **60 seconds** of waiting to the time estimate. A walk may contain **at most 2 crossings** (one there, one back). |
| **H7** | A walker may **arrive** at the point where a street meets a forbidden road and **turn around**. They may never continue onto the forbidden road. These dead-end nodes have `kind: 'terminus'`. |
| **H8** | Never routed at all: the Long Island Expressway, the Northern State Parkway, the Park at East Hills (residents and guests with a park card only), and any way that is private or `access=no|private`. |

### 1.1 What "along" means (be strict)

A segment is "along" a forbidden road if **any** of these is true. Treat all of them as forbidden:

1. Its street name, after normalisation (§1.2), **exactly equals** `glen cove road` or `northern boulevard`, in any one part of a multi-name such as `"Teakwood Ln / Glen Cove Rd"`.
2. Its OSM `ref` is `NY 25A` (Northern Boulevard).
3. It is a **sidewalk, footway or path that runs parallel to** a forbidden road: within **25 m** of the road's centreline and within **30°** of its bearing for more than **30 m**. Walking on the sidewalk of Glen Cove Road is still walking along it.
4. It is a **service road or parking aisle that only connects to a forbidden road** and is used to avoid H1/H2 (a "shortcut" along the road). Drop it.

**The substring trap.** *Old Northern Boulevard* is a different road in Roslyn village and **is allowed**. Never test with `includes('northern')` or a regex without anchors. Compare whole normalised names only. Acceptance check **A13** tests this.

**Where a street meets the road** (for example the east end of Elm Drive at Glen Cove Road): the node is a `terminus`. The walker may reach it and turn back. This is allowed because they are on Elm Drive, not on Glen Cove Road.

### 1.2 `lib/rules.ts` (new file; the only place these checks live)

No other file may re-implement a rule. Everything else imports from here.

```ts
// FILE: lib/rules.ts
import type { NodeId, Segment, WalkNode } from './types';

export type ForbiddenRoad = 'glen cove road' | 'northern boulevard';

/** Normalised names of the roads nobody may walk along. */
export const FORBIDDEN_ALONG: readonly ForbiddenRoad[] = ['glen cove road', 'northern boulevard'];
/** OSM `ref` values (normalised) that identify a forbidden road. NY 25A is Northern Boulevard. */
export const FORBIDDEN_REFS: readonly string[] = ['ny 25a'];

/** Segment ids that may cross a forbidden road. Nothing else may. */
export const GLEN_COVE_CROSSINGS: readonly string[] = ['X01'];   // Midwood Cross <-> Lakeville Ct/Dr, at the signal
export const NORTHERN_CROSSINGS: readonly string[] = [];         // none whitelisted (H5)

export const MAX_CROSSINGS_PER_WALK = 2;
export const CROSSING_WAIT_SECONDS = 60;
/** Footways closer than this and roughly parallel to a forbidden road count as "along" it (pipeline). */
export const PARALLEL_BUFFER_M = 25;
export const PARALLEL_MAX_BEARING_DIFF_DEG = 30;
export const PARALLEL_MIN_LENGTH_M = 30;

const ABBREVIATIONS: ReadonlyArray<readonly [RegExp, string]> = [
  [/\bblvd\b/g, 'boulevard'], [/\brd\b/g, 'road'], [/\bdr\b/g, 'drive'], [/\bln\b/g, 'lane'],
  [/\bave\b/g, 'avenue'], [/\bst\b/g, 'street'], [/\bct\b/g, 'court'], [/\bpl\b/g, 'place'],
  [/\bter\b/g, 'terrace'], [/\bcir\b/g, 'circle'], [/\bpkwy\b/g, 'parkway'],
];

/** Lower-case, drop parentheticals and punctuation, expand abbreviations, collapse spaces. */
export function norm(s: string): string {
  let t = s.toLowerCase().replace(/\([^)]*\)/g, ' ').replace(/[.,]/g, ' ');
  for (const [re, to] of ABBREVIATIONS) t = t.replace(re, to);
  return t.replace(/\s+/g, ' ').trim();
}

/** Which forbidden road (if any) does this name/ref belong to? Exact whole-name match only. */
export function forbiddenRoadOf(street: string, ref?: string): ForbiddenRoad | null {
  for (const part of street.split(/\s*[\/;]\s*/)) {
    const n = norm(part);
    const hit = FORBIDDEN_ALONG.find((f) => f === n);
    if (hit) return hit;
  }
  if (ref && ref.split(';').some((r) => FORBIDDEN_REFS.includes(norm(r)))) return 'northern boulevard';
  return null;
}

export function isWhitelistedCrossing(segmentId: string): boolean {
  return GLEN_COVE_CROSSINGS.includes(segmentId) || NORTHERN_CROSSINGS.includes(segmentId);
}

/** True if this segment may appear in the walkable graph. */
export function isLegalSegment(s: Pick<Segment, 'id' | 'street' | 'kind' | 'ref'>): boolean {
  if (s.kind === 'crossing') return isWhitelistedCrossing(s.id);
  return forbiddenRoadOf(s.street, s.ref) === null;
}

export interface PathCheck { ok: boolean; reasons: string[]; crossings: number; waitSeconds: number }

/**
 * Validate a node path against the hard rules. `between` returns the segment joining two nodes
 * (either direction) or undefined. Use this in the composer, the premium validator, the library
 * builder, the Maps link builder and the acceptance script.
 */
export function checkPath(
  path: readonly NodeId[],
  between: (a: NodeId, b: NodeId) => Segment | undefined,
  nodes: Readonly<Record<string, WalkNode>>,
): PathCheck {
  const reasons: string[] = [];
  let crossings = 0;
  for (let i = 0; i < path.length - 1; i++) {
    const a = path[i]!;
    const b = path[i + 1]!;
    const s = between(a, b);
    if (!s) { reasons.push(`no segment between ${a} and ${b}`); continue; }
    if (s.kind === 'crossing') {
      crossings++;
      if (!isWhitelistedCrossing(s.id)) reasons.push(`${s.id} is a crossing that is not whitelisted`);
    } else {
      const road = forbiddenRoadOf(s.street, s.ref);
      if (road) reasons.push(`${s.id} (${s.street}) walks along ${road}`);
    }
  }
  for (let i = 1; i < path.length - 1; i++) {
    if (nodes[path[i]!]?.kind === 'terminus' && path[i - 1] !== path[i + 1]) {
      reasons.push(`${path[i]} is a dead end at a forbidden road; the walk must turn back there`);
    }
  }
  if (crossings > MAX_CROSSINGS_PER_WALK) {
    reasons.push(`${crossings} crossings; the limit is ${MAX_CROSSINGS_PER_WALK}`);
  }
  return { ok: reasons.length === 0, reasons, crossings, waitSeconds: crossings * CROSSING_WAIT_SECONDS };
}
```

### 1.4 Where the rules are enforced (six places, all must hold)

| # | Place | How |
|---|---|---|
| 1 | **Graph builder** (`scripts/osm/build-graph.ts`, §6) | Forbidden and parallel edges are removed from the walkable graph and written to `BARRIERS` (display only). Dead ends at a forbidden road become `terminus` nodes. |
| 2 | **`lib/graph.ts`** | `buildAdjacency` calls `isLegalSegment`; the composer therefore cannot see a forbidden edge. The §5 validators call `checkPath` too. |
| 3 | **Composer and library** (`lib/compose.ts`, `scripts/build-library.ts`) | Reject any candidate with `checkPath(...).ok === false`. Count crossing waits in time (CLAUDE.md §9.3). |
| 4 | **Premium** (`lib/ai.ts`, `app/api/plan/route.ts`) | The prompt lists no forbidden edge, states H1 – H8, and the server validator runs `checkPath` (§8.5). |
| 5 | **Maps link** (`lib/maps.ts`) | Waypoints are chosen so that Google's likely shortest path does not use a barrier edge (§8.4). The UI says plainly that Google may choose its own path between pins. |
| 6 | **Tests** | A13 – A16 (§9) fail the build if any route, library entry or generated edge breaks a rule. |

### 1.5 What happens to the user's request

- A user who types "walk me along Glen Cove Road" or "take me down Northern Boulevard" in premium mode gets a route that avoids it, and the caveat: **"I don't route along Glen Cove Road or Northern Boulevard."**
- A walk that needs the signal (East Hills) shows a **crossing step** in Directions (§8.2) and adds a minute per crossing.
- The wizard never offers a stop that is only reachable by breaking a rule (§8.3).

### 6.3 Build steps (`scripts/osm/build-graph.ts`)

Do these in order. Put the rule logic in `lib/rules.ts` (§1.2) and `scripts/osm/forbidden.ts` (§6.4); do not re-implement it inline.

1. **Drop what is never walkable (H8):** motorways and trunks (LIE, Northern State Pkwy); ways with `access` in `no|private|permit|customers`; `foot` in `no|private`; `service` in `driveway|parking_aisle`; anything inside the Park at East Hills polygon; `highway=steps` is **kept** but flagged `steps: true` (the app notes "stairs" in directions; they are not excluded).
2. **Classify forbidden ways (H1, H2).** A way is forbidden if `forbiddenRoadOf(name, ref)` returns a road. Compare whole normalised names only (the `Old Northern Boulevard` trap, A13). Collect their centrelines as `barriers`.
3. **Drop parallel footways (H1 rule 3).** For every `footway`, `path`, `pedestrian`, `cycleway` and `service` way, drop it if `isParallelToForbidden(geometry, barrierLines)` (§6.4). A way that merely *crosses* a forbidden road at a steep angle is **kept** as a street piece up to the kerb, and the crossing itself is **not** created (step 6).
4. **Build topology.** Nodes shared by two or more ways, or with degree ≠ 2, are junctions. Contract degree-2 chains into one segment each, keeping the full geometry. Length = sum of great-circle distances along the geometry (not the router length).
5. **Name and tag each segment.** `street` = the way's `name` (join distinct names with `" / "`, primary first), `ref` from OSM, `traffic` from the table in §6.5, `scenic` from §6.5, `src: 'osm'`. If two chained ways have different names the segment is split at the name change (directions need real street names).
6. **Terminus nodes (H7).** Where a kept segment ends at a junction that also touches a removed forbidden way, mark that node `kind: 'terminus'`. It keeps its kept segment(s) and nothing else: no edge onto the forbidden road exists.
7. **The one crossing (H4).** Snap the seed coordinates of `GC_MIDWOOD` and `GCX_E` to the nearest generated nodes on Midwood Cross and Lakeville Ct/Dr (within 40 m, else **stop and report**). Create exactly one segment between them: `id: 'X01'`, `kind: 'crossing'`, `street: 'Glen Cove Rd crossing (signal)'`, `traffic: 3`, `src: 'assumed'`, `meters` = the measured distance across the road between the two snapped nodes (at least 15 m; if the measurement is odd, use 20), straight 2-point `geom`. **No other crossing segment may ever be created by the script.** Add a `Crossing` record (`verified: 'owner'`; add `osm` only if an OSM signal/crossing node is within 30 m of both ends).
8. **Reachability.** Keep the connected component that contains `HOME`; write the rest to `reports/connectivity.md` with the reason each piece is cut off (usually "only reachable along a forbidden road").
9. **Elevation.** Sample USGS 3DEP (EPQS, `https://epqs.nationalmap.gov/v1/json?x=<lon>&y=<lat>&wkid=4326&units=Feet&includeDate=false`) at every junction and about every 40 m along each segment. Cache every answer. Apply a 3-point median filter along each segment to remove spikes, round to whole feet. If EPQS cannot be reached after three polite attempts, **stop and report**; never invent elevations. Node `elevFt` = the sample at the node.
10. **Geometry.** Simplify each segment's geometry (Douglas–Peucker, 2 m), encode as a Google polyline (precision 5) into `geom`, and store `elevs` as `n = ceil(meters / 40) + 1` values sampled evenly **by arc length** along the simplified `geom` (first = node a, last = node b). The map and the elevation profile both read these.
11. **Write outputs deterministically** (stable sort by id, fixed number formatting). Running the script twice on the same cache must produce byte-identical files; print a SHA-256 of each.

```ts
  PARALLEL_BUFFER_M,
  PARALLEL_MAX_BEARING_DIFF_DEG,
  PARALLEL_MIN_LENGTH_M,
} from '../../lib/rules';

/** [lat, lon] in degrees. */
export type LatLon = readonly [number, number];
type XY = readonly [number, number];

const STEP_M = 5;
const LAT_M = 111_034;   // metres per degree of latitude near 40.8 N

function toXY(line: readonly LatLon[], lat0: number): XY[] {
  const lonM = 111_320 * Math.cos((lat0 * Math.PI) / 180);
  return line.map((p): XY => [p[1] * lonM, p[0] * LAT_M]);
}

function densify(line: readonly XY[], step: number): XY[] {
  const out: XY[] = [line[0]!];
  for (let i = 1; i < line.length; i++) {
    const a = line[i - 1]!;
    const b = line[i]!;
    const n = Math.max(1, Math.ceil(Math.hypot(b[0] - a[0], b[1] - a[1]) / step));
    for (let k = 1; k <= n; k++) out.push([a[0] + ((b[0] - a[0]) * k) / n, a[1] + ((b[1] - a[1]) * k) / n]);
  }
  return out;
}

/** Bearing of a -> b in degrees, folded to 0..180 (direction of travel does not matter). */
function axisDeg(a: XY, b: XY): number {
  const d = (Math.atan2(b[0] - a[0], b[1] - a[1]) * 180) / Math.PI;
  return ((d % 180) + 180) % 180;
}

function axisDiff(x: number, y: number): number {
  const d = Math.abs(x - y);
  return Math.min(d, 180 - d);
}

function distPointSeg(p: XY, a: XY, b: XY): number {
  const dx = b[0] - a[0];
  const dy = b[1] - a[1];
  const len2 = dx * dx + dy * dy;
  const t = len2 === 0 ? 0 : Math.max(0, Math.min(1, ((p[0] - a[0]) * dx + (p[1] - a[1]) * dy) / len2));
  return Math.hypot(p[0] - (a[0] + t * dx), p[1] - (a[1] + t * dy));
}

/**
 * Longest contiguous stretch (metres) of `candidate` that stays within PARALLEL_BUFFER_M of one of
 * the forbidden `roads` while running within PARALLEL_MAX_BEARING_DIFF_DEG of its direction.
 */
export function parallelRunMeters(candidate: readonly LatLon[], roads: ReadonlyArray<readonly LatLon[]>): number {
  if (candidate.length < 2) return 0;
  const lat0 = candidate[0]![0];
  const cand = densify(toXY(candidate, lat0), STEP_M);
  const roadsXY = roads.map((r) => toXY(r, lat0));
  let run = 0;
  let best = 0;
  for (let i = 0; i + 1 < cand.length; i++) {
    const a = cand[i]!;
    const b = cand[i + 1]!;
    const len = Math.hypot(b[0] - a[0], b[1] - a[1]);
    if (len === 0) continue;
    const mid: XY = [(a[0] + b[0]) / 2, (a[1] + b[1]) / 2];
    const axis = axisDeg(a, b);
    let near = false;
    for (const road of roadsXY) {
      for (let j = 0; j + 1 < road.length && !near; j++) {
        const c = road[j]!;
        const d = road[j + 1]!;
        near = distPointSeg(mid, c, d) <= PARALLEL_BUFFER_M && axisDiff(axis, axisDeg(c, d)) <= PARALLEL_MAX_BEARING_DIFF_DEG;
      }
      if (near) break;
    }
    if (near) { run += len; best = Math.max(best, run); } else run = 0;
  }
  return best;
}

export function isParallelToForbidden(candidate: readonly LatLon[], roads: ReadonlyArray<readonly LatLon[]>): boolean {
  return parallelRunMeters(candidate, roads) >= PARALLEL_MIN_LENGTH_M;
}
```

- Trust OpenStreetMap when they disagree (rule 0.5). **Stop and report** if more than 10 % of seed segments fail the 12 % check or any seed node has no match: the bounding box or the snapping is wrong.

### 6.8 The macro graph (`data/generated/macro.ts`)

A walk planner does not need every kink. Build a smaller **macro graph** from the legal graph:

- **Decision nodes:** `HOME`, every junction of degree ≥ 3, every `poi`, `terminus` and `crossing` node.
- **Macro edges:** each chain of segments between two decision nodes, with `via` = the ordered segment ids, summed `meters`, summed climb/drop, the dominant street name, and the worst `traffic`.
- A dead-end stub shorter than 150 m folds into its parent node as `stub: { meters }` (optional out-and-back worth `2 × meters`); it does not become a node.
- Target **120 – 220 decision nodes.** If outside that range, stop and report rather than tuning thresholds silently.

Premium mode (§8.5) and the library builder both use the macro graph, so the model sees a catalogue small enough for a prompt and every answer expands to real segments.

### 6.9 The route library (`scripts/build-library.ts` → `data/generated/library.ts`)

With the full graph, enumerating every closed walk is too big (the seed alone has 13,042). Build a **bounded library once, at build time**, and ship only that:

1. Generate candidate closed walks from `HOME` on the **macro graph**: out-and-backs to every decision node within 3.75 mi; simple cycles through `HOME` up to 7.5 mi; lollipops (stem + cycle + stem). Cap the search at **250,000 expansions**; stop early if reached and print that it did.
2. Keep a candidate only if `checkPath(...).ok`, length 0.4 – 7.5 mi, no segment used more than twice, at most 2 crossings.
3. Score each with the unchanged `CLAUDE.md` §9.2 mood weights and compute time (`CLAUDE.md` §9.3 plus crossing waits).
4. Select per **mood (clear / workout / ponder) × distance bucket (< 1.5, 1.5 – 3, 3 – 5, 5+ mi)** the best **24**, greedily: take the highest score whose edge-set Jaccard similarity with every route already chosen in that bucket is **≤ 0.55**.
5. Name and write each blurb with the `CLAUDE.md` §8.3 generator **at build time** and store them.
6. **If any mood × bucket has fewer than 6 routes, stop and report** (rule 0.6) with the counts; do not lower the similarity threshold to pad.

At runtime in Stage 2 the pool is **curated ∪ library**; `lib/compose.ts` is kept for seed mode (`GRAPH_SOURCE = 'seed' | 'generated'` in `lib/config.ts`). Curated routes that do not exist in the generated graph are dropped with a warning in `reports/seed-diff.md`.

## 7. The accurate map (replaces `RouteSketch`, `CLAUDE.md` §12.4 and the sketch half of §15.7)

### 7.1 What was wrong, and what "accurate" means

The old `RouteSketch` joined node coordinates with straight lines. It showed no street shapes, no neighbouring streets, no roads she must not walk, and no scale. The new map is a **real street map drawn from stored OpenStreetMap geometry**:

1. Every segment is drawn with its **actual curve** (`geom`), not a chord.
2. The **legal network** is visible as faint context, so she sees where the route sits among the streets.
3. **Glen Cove Road and Northern Boulevard are drawn as dashed "Not walked" lines** with labels, and the **signal crossing** is drawn and labelled where a route uses it.
4. There is a **scale bar**, a **north arrow**, **numbered step markers** that match the Directions list, **direction chevrons**, **street labels**, and an **elevation scrub dot** linked to the profile.
5. Nothing is invented: no smoothing, no extrapolation, no guessing between points. A segment with no stored geometry is drawn as a **dashed straight line** and the map shows an "approximate" chip.
6. An optional photographic-quality street **basemap** can be switched on (§7.6). It is **off by default**.

The map needs the geometry produced in Stage 2 (§6). In seed-only mode (Overpass unreachable) it falls back to point-to-point lines through node coordinates, draws them dashed, and shows the "approximate" chip; it never pretends to be more exact than the data.

### 7.2 Geometry and projection helpers (compile-checked; port exactly)

`geom` is a Google-encoded polyline (precision 5, `[lat, lon]` pairs) of a segment's centreline from node `a` to node `b`. `elevs` are feet, sampled evenly by arc length along `geom`.

```ts
// FILE: lib/polyline.ts
export type LatLon = readonly [number, number];

export function decodePolyline(str: string, precision = 5): LatLon[] {
  const factor = 10 ** precision;
  const out: LatLon[] = [];
  let index = 0;
  let lat = 0;
  let lon = 0;
  while (index < str.length) {
    for (let axis = 0; axis < 2; axis++) {
      let result = 0;
      let shift = 0;
      let b: number;
      do {
        b = str.charCodeAt(index++) - 63;
        result |= (b & 0x1f) << shift;
        shift += 5;
      } while (b >= 0x20);
      const delta = result & 1 ? ~(result >> 1) : result >> 1;
      if (axis === 0) lat += delta; else lon += delta;
    }
    out.push([lat / factor, lon / factor]);
  }
  return out;
}

function encodeValue(v: number): string {
  let n = v < 0 ? ~(v << 1) : v << 1;
  let s = '';
  while (n >= 0x20) {
    s += String.fromCharCode((0x20 | (n & 0x1f)) + 63);
    n >>= 5;
  }
  return s + String.fromCharCode(n + 63);
}

export function encodePolyline(points: readonly LatLon[], precision = 5): string {
  const factor = 10 ** precision;
  let prevLat = 0;
  let prevLon = 0;
  let out = '';
  for (const [la, lo] of points) {
    const a = Math.round(la * factor);
    const o = Math.round(lo * factor);
    out += encodeValue(a - prevLat) + encodeValue(o - prevLon);
    prevLat = a;
    prevLon = o;
  }
  return out;
}
```

```ts
// FILE: lib/geo.ts
import type { LatLon } from './polyline';

const R_EARTH_M = 6_371_008.8;
const rad = (d: number): number => (d * Math.PI) / 180;

export function haversineM(a: LatLon, b: LatLon): number {
  const dLat = rad(b[0] - a[0]);
  const dLon = rad(b[1] - a[1]);
  const h = Math.sin(dLat / 2) ** 2 + Math.cos(rad(a[0])) * Math.cos(rad(b[0])) * Math.sin(dLon / 2) ** 2;
  return 2 * R_EARTH_M * Math.asin(Math.min(1, Math.sqrt(h)));
}

export function cumulativeM(pts: readonly LatLon[]): number[] {
  const out: number[] = [0];
  for (let i = 1; i < pts.length; i++) out.push(out[i - 1]! + haversineM(pts[i - 1]!, pts[i]!));
  return out;
}

export function pathLengthM(pts: readonly LatLon[]): number {
  const c = cumulativeM(pts);
  return c[c.length - 1] ?? 0;
}

/** Point at `distM` along the polyline (clamped), linear between vertices. */
export function pointAtDistance(pts: readonly LatLon[], cum: readonly number[], distM: number): LatLon {
  if (pts.length === 0) throw new Error('empty polyline');
  const total = cum[cum.length - 1]!;
  const d = Math.max(0, Math.min(total, distM));
  let i = 1;
  while (i < cum.length - 1 && cum[i]! < d) i++;
  if (pts.length === 1) return pts[0]!;
  const span = cum[i]! - cum[i - 1]!;
  const t = span === 0 ? 0 : (d - cum[i - 1]!) / span;
  const a = pts[i - 1]!;
  const b = pts[i]!;
  return [a[0] + (b[0] - a[0]) * t, a[1] + (b[1] - a[1]) * t];
}

/** Local metric projection: x metres east, y metres SOUTH (screen-down) of `origin`. */
export function makeProjector(origin: LatLon): (p: LatLon) => readonly [number, number] {
  const mPerLat = (Math.PI / 180) * R_EARTH_M;
  const mPerLon = mPerLat * Math.cos(rad(origin[0]));
  return (p) => [(p[1] - origin[1]) * mPerLon, -(p[0] - origin[0]) * mPerLat];
}

export interface View { scale: number; cx: number; cy: number }   // px per metre, centre in projected metres

/** The view that fits every point into width x height with `pad` px around. */
export function fitView(pointsXY: ReadonlyArray<readonly [number, number]>, width: number, height: number, pad: number): View {
  if (pointsXY.length === 0) return { scale: 1, cx: 0, cy: 0 };
  let minX = Infinity; let maxX = -Infinity; let minY = Infinity; let maxY = -Infinity;
  for (const [x, y] of pointsXY) {
    if (x < minX) minX = x; if (x > maxX) maxX = x;
    if (y < minY) minY = y; if (y > maxY) maxY = y;
  }
  const w = Math.max(maxX - minX, 1);
  const h = Math.max(maxY - minY, 1);
  const scale = Math.min((width - 2 * pad) / w, (height - 2 * pad) / h);
  return { scale, cx: (minX + maxX) / 2, cy: (minY + maxY) / 2 };
}

/** A "nice" scale-bar length in metres for a given px-per-metre scale, at most `maxPx` wide. */
export function niceScaleBarM(scale: number, maxPx: number): number {
  const steps = [10, 20, 50, 100, 200, 250, 500, 1000, 2000];
  let best = steps[0]!;
  for (const s of steps) if (s * scale <= maxPx) best = s;
  return best;
}
```

```ts
// FILE: lib/routeGeometry.ts
import type { NodeId, Segment, WalkNode } from './types';
import type { LatLon } from './polyline';
import { decodePolyline } from './polyline';

export interface RouteGeometry {
  points: LatLon[];          // the whole walk, in order, with no duplicated joints
  stepStart: number[];       // index in `points` where each path step begins (length = path.length - 1)
  approximate: boolean;      // true if any step had no stored geometry (drawn as a straight chord)
}

/**
 * Build the drawn line for a walk. For each step a -> b: use the segment's `geom` (reversed when the
 * walk goes b -> a); if there is none, fall back to the two node coordinates and flag `approximate`.
 */
export function routeGeometry(
  path: readonly NodeId[],
  between: (a: NodeId, b: NodeId) => Segment | undefined,
  geomOf: (segmentId: string) => string | undefined,
  nodes: Readonly<Record<string, WalkNode>>,
): RouteGeometry {
  const points: LatLon[] = [];
  const stepStart: number[] = [];
  let approximate = false;
  for (let i = 0; i < path.length - 1; i++) {
    const a = path[i]!;
    const b = path[i + 1]!;
    const seg = between(a, b);
    const encoded = seg ? geomOf(seg.id) : undefined;
    let piece: LatLon[];
    if (seg && encoded) {
      piece = decodePolyline(encoded);
      if (seg.a !== a) piece = piece.slice().reverse();
    } else {
      const na = nodes[a];
      const nb = nodes[b];
      if (!na || !nb) throw new Error(`unknown node in path: ${a} or ${b}`);
      piece = [[na.lat, na.lon], [nb.lat, nb.lon]];
      approximate = true;
    }
    stepStart.push(points.length === 0 ? 0 : points.length - 1);
    points.push(...(points.length === 0 ? piece : piece.slice(1)));
  }
  return { points, stepStart, approximate };
}
```

### 7.4 Accuracy rules (the map must obey these)

- Draw only stored geometry. The drawn route is the concatenation from `routeGeometry`; its measured length (`pathLengthM`) must agree with the route's `meters` within **1.5 %** in generated mode (simplification shortens slightly). Acceptance **A21**.
- The drawn route never touches a barrier line except at the crossing `X01` and at `terminus` ends (A22 checks that no drawn point of a route lies within 12 m of a barrier centreline other than within 40 m of those nodes).
- The scale bar, step markers and chevrons derive from the same projection as the lines. No separate "pretty" layout.
- The "approximate" chip appears when `RouteGeometry.approximate` is true, and always in seed-only mode.

### 7.5 Elevation profile and stats from real samples

When `elevs` exist (generated mode), `ElevationProfile` plots the **sampled** values along the route (concatenated, reversed when walked b → a), not node-to-node straight lines. `ascentFt` / `descentFt` are the sums of positive / negative changes of the **median-filtered** samples ignoring changes under **2 ft** (noise deadband). This replaces the node-to-node lower bound in generated mode; seed mode keeps node-to-node and the §5.2 test vector. The 3-minutes-per-100-ft time rule (CLAUDE.md §9.3) uses whichever ascent is in force.

**The danger this addendum adds.** Google chooses its own walking path between the pins, and the shortest path may run along Glen Cove Road or Northern Boulevard even though the app never would. So the waypoint chooser must **simulate Google on a graph that includes the roads we refuse**, and must add pins until the simulated path matches the intended route.

- `data/barrier-links.ts` lists those refused roads as edges between the street ends where they start and finish (for seed v3: the removed segments, below). In Stage 2 the pipeline writes the same file from the real forbidden ways.
- Simulation graph = legal segments ∪ `BARRIER_LINKS` (both directions). Barrier ids start with `B`.
- **Choose waypoints leg by leg.** Start with none. Split the intended walk at the chosen waypoints into legs. For each leg run Dijkstra (by metres) between its ends; a leg is exact when its edges equal the intended edges. If every leg is exact, stop. Otherwise take the leg whose interior has the node **farthest from that leg's simulated path** and add that node as a waypoint (keep waypoints in walking order). Stop at the limit. (Measuring against the whole simulated path, as the old text allowed, fails on out-and-backs because the outbound half is "near" the return half.)
- For a walk with a crossing the algorithm will pick one or both curbs of `X01` because the barrier link is shorter; that is intended. Never drop them to save a pin.
- If the limit is reached and the simulated path **still uses a barrier edge**, mark the walk `mapsRisky`: the Maps button gets a warning line, **"Google may take Glen Cove Road or Northern Boulevard between pins. Follow the Directions list instead."** The Directions list and the in-app map always show the true route. If the limit is reached without a barrier edge but the path differs, show the old line, "Google may pick a slightly different path on this one — the list above is the exact route."
- Out-and-backs and hill repeats: Google cannot be told to repeat a leg; accept "inexact" for hill-repeat routes (R19).

```ts
// FILE: lib/waypoints.ts
import type { LatLon } from './polyline';

export interface SimEdge { id: string; to: string; meters: number }
export type SimGraph = (node: string) => readonly SimEdge[];

export interface SimPath { nodes: string[]; edges: string[] }

/** Dijkstra by metres on a small graph. Returns null if `to` is unreachable. */
export function shortestPath(g: SimGraph, from: string, to: string): SimPath | null {
  if (from === to) return { nodes: [from], edges: [] };
  const dist = new Map<string, number>([[from, 0]]);
  const prev = new Map<string, { node: string; edge: string }>();
  const done = new Set<string>();
  for (;;) {
    let u: string | undefined;
    let best = Infinity;
    for (const [n, d] of dist) if (!done.has(n) && d < best) { best = d; u = n; }
    if (u === undefined) return null;
    if (u === to) break;
    done.add(u);
    for (const e of g(u)) {
      const nd = best + e.meters;
      if (nd < (dist.get(e.to) ?? Infinity) - 1e-9) { dist.set(e.to, nd); prev.set(e.to, { node: u, edge: e.id }); }
    }
  }
  const nodes: string[] = [to];
  const edges: string[] = [];
  for (let n = to; n !== from; ) {
    const p = prev.get(n)!;
    edges.push(p.edge);
    nodes.push(p.node);
    n = p.node;
  }
  return { nodes: nodes.reverse(), edges: edges.reverse() };
}

function approxM(a: LatLon, b: LatLon): number {
  return Math.hypot((a[0] - b[0]) * 111_034, (a[1] - b[1]) * 111_320 * Math.cos((a[0] * Math.PI) / 180));
}

export interface WaypointPlan {
  indices: number[];        // indices into `path`, ascending: the nodes to pass to Google as pins
  exact: boolean;           // every leg's simulated shortest path equals the intended edges
  usesBarrier: boolean;     // some simulated leg runs along a refused road
}

export function chooseWaypoints(
  path: readonly string[],
  pathEdges: readonly string[],            // edge id for each step, length path.length - 1
  g: SimGraph,
  coord: (node: string) => LatLon,
  isBarrierEdge: (edgeId: string) => boolean,
  limit: number,
): WaypointPlan {
  const chosen: number[] = [];
  for (;;) {
    const idx = [0, ...[...chosen].sort((x, y) => x - y), path.length - 1];
    let exact = true;
    let usesBarrier = false;
    let worst = -1;
    let worstD = -1;
    for (let k = 0; k + 1 < idx.length; k++) {
      const a = idx[k]!;
      const b = idx[k + 1]!;
      const sp = shortestPath(g, path[a]!, path[b]!);
      if (!sp) { exact = false; continue; }
      if (sp.edges.some(isBarrierEdge)) usesBarrier = true;
      const want = pathEdges.slice(a, b);
      if (sp.edges.length === want.length && sp.edges.every((e, i) => e === want[i])) continue;
      exact = false;
      for (let i = a + 1; i < b; i++) {
        const c = coord(path[i]!);
        let d = Infinity;
        for (const n of sp.nodes) d = Math.min(d, approxM(c, coord(n)));
        if (d > worstD + 1e-9) { worstD = d; worst = i; }
      }
    }
    const indices = [...chosen].sort((x, y) => x - y);
    if (exact) return { indices, exact: true, usesBarrier: false };
    if (chosen.length >= limit || worst < 0 || worstD <= 0.5) return { indices, exact: false, usesBarrier };
    chosen.push(worst);
  }
}
```

```ts
  { name: 'diagonal at 45 degrees', way: [at(-40, 300), at(40, 380)], parallel: false },
];

export function runRuleVectors(): string[] {
  const failures: string[] = [];
  for (const [street, ref, want] of NAME_CASES) {
    const got = forbiddenRoadOf(street, ref);
    if (got !== want) failures.push(`forbiddenRoadOf(${JSON.stringify(street)}, ${JSON.stringify(ref)}) = ${got}, wanted ${want}`);

    const got = isParallelToForbidden(c.way, ROAD);
    if (got !== c.parallel) failures.push(`geometry "${c.name}": got ${got}, wanted ${c.parallel}`);
  }
```
